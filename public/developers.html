QWALLADeveloper integration

Connect your site to the Qwalla wallet

Qwalla injects a wallet provider into any website opened inside its in-app dApp browser (iOS/Android) and the Qwalla Browser desktop app. Your site talks to the user's RougeChain wallet through a single global — window.rougechain — to read their address/balance, request signatures, and send transactions. Every state-changing action prompts the user inside the wallet; the private key never leaves it.

This is not an EVM / EIP-1193 provider. RougeChain is a post-quantum chain (ML-DSA-65 signatures, ML-KEM-768 encryption), so the method set is RougeChain-native. There is no window.ethereum.

1 · Detect the provider

The provider is injected before your page scripts and is a frozen object. Detect it synchronously, or wait for the rougechain#initialized event.

function getQwalla() {
  return typeof window !== 'undefined' && window.rougechain?.isRougeChain
    ? window.rougechain
    : null;
}

let qwalla = getQwalla();                       // already there?
window.addEventListener('rougechain#initialized', () => {
  qwalla = getQwalla();                         // …or wait for it
});

If window.rougechain is absent, the page isn't running inside Qwalla — show your "Open in Qwalla" prompt.

2 · Connect

connect() prompts the user once per origin; later calls from an approved origin resolve immediately.

const { publicKey, network } = await window.rougechain.connect();
// publicKey → the user's ML-DSA-65 wallet public key (their identity)
// network   → 'mainnet' | 'testnet' | …

Rejected connections throw — wrap calls in try/catch.

3 · Methods

All methods return a Promise. Approval-gated methods show the wallet's approval sheet; reads don't. Requests time out after 120 s.

Examples

// Send 25 XRGE
const { txId } = await window.rougechain.sendTransaction({
  payload: { to: 'rouge1…', amount: 25, token: 'XRGE' },
});

// Sign a payload (deep key-sorted + UTF-8 encoded before signing).
// Pass serializedHex instead to sign exact bytes.
const { signature } = await window.rougechain.signTransaction({
  payload: { action: 'login', nonce: '…' },
});

// Approve a spender, then swap
await window.rougechain.approve({ spender: 'rouge1…', amount: 100, token: 'XRGE' });
await window.rougechain.swap({ tokenIn: 'XRGE', tokenOut: 'qUSDC', amountIn: 100 });
Fees: RougeChain charges a flat 1 XRGE per transaction; any fee you pass is informational and may be overridden by the node. XRGE amounts are whole numbers (decimals are dropped); other tokens keep their decimals.

4 · Events

window.rougechain.on('accountsChanged', (publicKey) => { /* re-read state */ });
window.rougechain.on('networkChanged',  (network)   => { /* switch RPC/UI  */ });
window.rougechain.on('disconnect',      ()          => { /* reset session  */ });

Always re-fetch balance/identity on accountsChanged — the user may have switched accounts in the wallet.

5 · End-to-end messaging bridge optional

If your dApp has encrypted DMs, it can share Qwalla's messaging identity instead of maintaining its own. Once connected:

  • getEncryptionPublicKey() returns the wallet's native ML-KEM-768 public key — publish/look it up so peers can encrypt to the user.
  • decrypt(envelope) decrypts a message addressed to the user inside the wallet (the KEM secret never leaves it). Legacy {v:1,keys} envelopes are supported for backward compatibility.

This lets a dApp's inbox interoperate with Qwalla's own Chats, using the shared deriveRougeeKem(mnemonic, …|rougee-gram|kem-v1) derivation standard.

Notes & gotchas

  • Approval is mandatory for sendTransaction, signTransaction, approve, swap, and callContract. If the user dismisses the sheet, the promise rejects.
  • One origin = one connection. Connection approval is remembered per origin.
  • Works identically in the mobile in-app browser and the Qwalla Browser desktop app — same provider, same protocol.
